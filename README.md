# Finance Jarvis

한국투자증권(KIS) OpenAPI로 국내 주식·ETF를 자동매매하는 개인 프로젝트다. 세 부분으로 되어 있다.

- 자동매매 엔진: 30분마다 등록한 종목을 돌면서 매수/매도를 판단한다. 일봉 지표, 30분봉, 뉴스 감성, (선택) 밸류에이션을 합친 시그널을 쓰고, 손절과 트레일링 익절은 언제나 먼저 본다.
- AI 포트폴리오 에이전트: 코스피·코스닥 전 종목에서 매일 후보를 찾고, Gemini가 비중 조정과 종목 편입/제외를 제안한다. 내가 승인해야 반영된다.
- 매매 복기 대시보드: 쌓인 체결·판단 기록으로 손익을 보고 그날의 판단을 다시 따져 본다.

기본값은 모의투자, 국내 전용이다. 실거래는 설정을 두 군데 바꿔야 켜진다.

## 빠른 시작

필요한 것:

- Python 3.12 이상, [uv](https://docs.astral.sh/uv/)
- KIS OpenAPI 앱키와 시크릿 (모의투자용). 계좌가 모의투자 주문서비스에 신청되어 있어야 한다.
- KIS HTS ID (체결통보 웹소켓에 필요)
- Gemini API 키 (선택). 없으면 뉴스 감성과 AI 제안이 꺼지고 기술적 지표만 쓴다.

설치:

```bash
uv sync
cp .env.template .env
```

`.env`에는 최소한 아래를 채운다.

```dotenv
KIS_APP_KEY=...
KIS_APP_SECRET=...
KIS_ACCOUNT_NO="12345678-01"
KIS_HTS_ID=...
IS_MOCK=True
GEMINI_API_KEY=...   # 선택
```

손절 폭, 주문 한도, 발굴 가중치 같은 나머지 설정은 `.env.template`에 주석으로 있고 기본값은 [core/config.py](core/config.py)에 있다.

터미널 두 개로 실행한다.

```bash
# 1. API 서버 (엔진이 실제로 도는 곳)
uv run uvicorn api.main:app --port 8800

# 2. 대시보드
uv run streamlit run app.py
```

브라우저에서 `http://localhost:8501`을 연다. API 코드를 고쳤다면 uvicorn을 다시 띄워야 한다.

처음 쓰는 순서는 이렇다.

1. KIS 자동매매 페이지의 포트폴리오 탭에서 종목을 등록한다 (예: 삼성전자 `005930`, KODEX 200 `069500`).
2. 목표 비중을 직접 넣거나, AI 에이전트 탭에서 제안을 받아 승인한다.
3. 개요 탭에서 시작 버튼을 누른다. 엔진은 평일 09:00~15:30에만 움직인다.
4. 며칠 지난 뒤 매매 복기·분석 페이지에서 결과를 본다.

테스트는 `uv run pytest`.

실전투자로 바꾸려면 `IS_MOCK=False`만으로는 안 되고 `I_UNDERSTAND_REAL_MONEY_RISK=true`도 같이 있어야 한다. 하나만 바꿔서 실수로 실거래가 시작되는 걸 막으려는 장치다. 처음에는 모의투자로 며칠 돌려 보는 걸 권한다.

## 페이지

좌측 메뉴에 두 페이지가 있다. 둘 다 8800번 포트의 API 서버에 붙으므로 서버가 꺼져 있으면 안내 메시지가 뜬다.

### 매매 복기·분석

읽기 전용이다. 체결(`fills`)과 판단(`decision_log`), 리밸런싱 기록으로 성과를 계산해서 보여주기만 하고 매매에는 관여하지 않는다. 사이드바에서 분석 기간(7~90일)과 색상 방식(한국식은 상승이 빨강)을 고를 수 있다. 데이터 새로고침은 KIS 일봉을 다시 받아오기 때문에 모의계좌에서는 꽤 느리다.

- 성과 오버뷰: 종목별 누적손익과 수익률, 일별 평가손익, 누적수익률과 낙폭, 종목×날짜 히트맵.
- 매매 달력: 월 달력에 일별 실현손익과 체결 건수를 표시한다. 날짜를 고르면 체결 내역이 나온다.
- 의사결정 복기: 가격 차트에 엔진의 매수/매도/관망 판단을 찍는다. 판단을 선택하면 당시 시그널과 뉴스·밸류에이션 근거, 손절 판정 같은 원본 기록을 펼쳐 볼 수 있다.
- 리밸런싱 이력: 리밸런싱 이벤트 목록, 목표 비중 변화, 승인 이후 성과를 이전 포트폴리오와 비교한다.

손익 계산에는 알아둘 점이 있다. 수수료와 세금은 빠져 있고, 입출금도 추적하지 않는다. 체결 기록이 없는 옛 매도는 판단 시점 가격으로 추정하며 화면에 `≈`로 표시한다.

### KIS 자동매매

엔진을 켜고 끄고, 포트폴리오와 AI 제안을 관리하는 페이지다. 사이드바에서 모의/실전 여부와 엔진 상태를 보고, 자동 새로고침(5~60초)을 켤 수 있다.

- 개요: 엔진 상태(하트비트, 체결통보 웹소켓, 킬스위치)와 시작/정지/긴급정지 버튼. 긴급정지는 미체결 주문을 전부 취소한다. 보유 종목의 비중 파이차트도 여기 있다.
- 설정 · 리스크: 지금 적용 중인 설정값을 보여준다. 읽기 전용이라 바꾸려면 `.env`를 고치고 API를 재시작한다.
- 포트폴리오 · 비중: 종목 등록/삭제, 목표 비중 입력, 현재 포지션. 삭제한 종목은 바로 팔지 않고 정리 대기 상태가 된다 (아래 설명).
- AI 에이전트: 리밸런싱 제안 요청과 승인/거부, 자동 트리거 스케줄러 on/off, 종목 발굴 후보와 오늘의 발굴 결과, 보유 종목의 샤프·소티노·베타·MDD 같은 지표를 볼 수 있다.
- 매매 로그: 최근 판단 이력. 종목과 액션(BUY/SELL/NO_OP)으로 거를 수 있고, 손절·트레일링·스윙 같은 사유가 뱃지로 붙는다.

킬스위치가 발동하면 화면 위에 사유와 해제 버튼이 뜬다. 자동으로는 풀리지 않는다. 원인을 확인하고 직접 해제해야 한다.

## 어떻게 판단하나

### 평시 매매

`core/signal_engine.py`의 `decide()`가 종목당 사이클당 한 번 호출된다. 방향과 타이밍은 시그널이 정하고, 목표 비중 밴드는 상한 역할만 한다.

- 현재 비중이 목표+밴드+버퍼(기본 5%+5%)를 넘으면 시그널과 상관없이 그 선까지 줄인다. 반대로 비중이 낮다고 억지로 사지는 않는다.
- 그 외에는 결합 시그널 강도가 0.5를 넘을 때만 매매한다. 강도에 비례해 총자산의 최대 15%까지 거래한다.
- 결합 가중치는 일봉 기술 30%, 30분봉 50%, 뉴스 감성 20%, 밸류에이션 20%다. 없는 시그널은 빼고 다시 정규화한다.
- 새로 편입한 종목은 시그널과 무관하게 5일에 걸쳐 나눠 사서 목표 비중까지 채운다 (분할 온보딩).
- 모든 주문은 회당 금액(100만원)과 종목당 비중(30%) 한도로 한 번 더 잘린다.

### 손절과 트레일링 익절

`core/exit_guard.py`가 담당하고, 위의 판단보다 먼저 평가한다.

- 손절: 평단 대비 -7%면 전량 시장가 매도.
- 트레일링 익절: 고점이 평단보다 충분히 올랐던 포지션에만 적용한다. 고점에서 ATR 기반 폭(2.5×ATR%, 3~12% 사이)만큼 내려오면 전량 매도한다. ATR을 못 구하면 고점 대비 -5%를 쓴다.
- 이 둘은 재주문 쿨다운과 일일 손실 한도를 일부러 무시한다. 손실을 줄이는 매도가 "새 매매 제한"에 걸리면 안 되기 때문이다. 다만 VI(변동성 완화장치) 중에는 보류한다.

### 30분봉

KIS 국내 분봉 API는 1분봉만 준다. 09:00 기준으로 묶어서 30분봉을 만든다. 새로 등록한 종목은 봉이 30개 쌓일 때까지 과거 데이터를 채워야 하는데, 모의투자는 초당 1건 제한이 있어서 사이클마다 3종목씩만 처리한다. 그동안 그 종목은 HOLD 상태다.

### 뉴스 감성과 밸류에이션

네이버 금융 뉴스를 모아 새 기사만 Gemini에 보내 BUY/SELL/HOLD와 강도를 받는다. 종목별 감성은 12시간 반감기로 최근 기사에 더 무게를 둔 평균이다. LLM이 실패하면 HOLD로 처리한다.

밸류에이션은 기본으로 꺼져 있다(`ENABLE_FUNDAMENTAL_VALUATION`). 켜면 과거 PER/PBR 백분위, 네이버 컨센서스 목표가와의 괴리, 52주 범위 내 위치를 가중 합산한다. 정밀한 DCF가 아니라 어림잡는 휴리스틱이다.

### AI 포트폴리오 에이전트

1. 장 마감 후(16시 이후) 하루 한 번, KIS 전 종목 마스터에서 후보를 모은다. 소스는 모멘텀(등락률·거래량 순위), 증권사 리포트, 시장 뉴스 언급, 저평가(목표가 괴리), 테마 후발주 다섯 가지다. 후보마다 점수를 매겨 관점별로 골고루 숏리스트를 만든다. 레버리지·인버스 ETF는 뺀다.
2. 제안을 요청하면 현재 포트폴리오, 보유 종목 지표, 숏리스트, 시장 심리(CNN Fear & Greed)를 LLM에 주고 비중 조정과 편입/제외 안을 받는다. 후보 목록에 없는 종목은 낼 수 없다.
3. `core/ai_rebalance_guard.py`가 한도를 검사한다. 총 회전율 20%, 종목당 비중 변화 10%p, 편입·제외 각 2개 등이다. 하나라도 넘으면 숫자를 깎아서 맞추지 않고 제안 전체를 버린다.
4. 통과한 제안은 `PROPOSED`로 저장만 된다. 내가 승인해야 실제 목표 비중이 바뀐다.
5. 스케줄러(기본 꺼짐)를 켜면 30일마다, 비중이 밴드를 크게 벗어났을 때, 보유 종목에 강한 뉴스가 나왔을 때 제안을 자동으로 만든다. 승인은 여전히 사람이 한다. 스케줄러는 매매 엔진과 별개로 돈다.

### 종목을 삭제하면

바로 팔지 않는다. 신규 매수만 멈추고, 매도 신호가 나오면 전량 판다. 5일(`WINDDOWN_MAX_DAYS`)이 지나도 신호가 없으면 강제로 청산하고 포트폴리오에서 지운다. 삭제한 종목은 30일 동안 AI의 신규 편입 후보에서도 빠진다.

## 안전장치

- 모의투자 기본, 실전은 이중 확인 (`IS_MOCK`, `I_UNDERSTAND_REAL_MONEY_RISK`)
- 국내 전용 기본 (`DOMESTIC_ONLY`): 해외 종목은 등록이 거부되고 해외 API도 부르지 않는다. DB에 남은 해외 이력은 그대로 둔다.
- 같은 종목 재주문은 30분 간격 (손절/익절 제외)
- 일일 손실이 총자산의 3%에 닿으면 그날 신규 주문 중단
- 체결통보 웹소켓이 120초 넘게 조용하면 신규 주문 중단. 보유 종목의 손절 평가는 계속한다.
- 킬스위치: 등록 종목의 35% 이상이 VI/거래정지이거나 60초 안에 주문 거부가 3번 이상이면 자동으로 발동한다. 수동으로만 해제된다.
- `flock` 락으로 엔진이 두 개 뜨는 것을 막는다. 프로세스가 죽으면 OS가 락을 풀어준다.

## 알려진 한계

- 휴장일 캘린더가 없다. 평일 09:00~15:30으로만 판단한다.
- 수수료와 세금을 매매 판단에도, 손익 계산에도 반영하지 않는다. 신호가 자주 뒤집히면 잔 매매로 비용이 쌓일 수 있다.
- 스윙 1회 최대치(15%)가 작지 않다. 실전 전에 모의투자로 매매 빈도와 크기를 충분히 지켜볼 것.
- 개별 기능은 모의투자로 확인했지만, 엔진을 여러 날 연속으로 돌려 본 기간은 짧다.
- 해외 유망 종목은 직접 해외 실주문 대신 국내 상장 대체 ETF를 통한 프록시 대리 매매(`OVERSEAS_PROXY_TRADING_ENABLED=True`)로 환전·해외수수료 부담 없이 매매한다.
- 네이버(뉴스, 컨센서스, 리포트)와 CNN은 비공식 API라 언제든 바뀔 수 있다. 실패하면 해당 입력만 빠지고 나머지는 계속 돈다.

## 자주 보는 오류

- `EGW00133`: 토큰 발급은 모의투자에서 1분에 한 번만 된다. 잠시 뒤 다시 시도.
- `EGW00201`: 초당 호출 제한 초과. 클라이언트가 자동으로 속도를 낮추고 재시도한다.
- `EGW02006`: 모의투자는 매도가능수량 조회를 지원하지 않는다. 보유 수량으로 대신한다.
- `IGW00002`, `40910000`: 계좌가 모의투자 주문서비스에 등록되지 않았다.
- Gemini 404: 모델이 단종된 경우다. 에러 메시지에 나온 모델로 `GEMINI_MODEL`을 바꾼다. 5xx는 `GEMINI_FALLBACK_MODEL`이 받아준다.
- 대시보드에 "제어 플레인에 연결할 수 없습니다": uvicorn이 꺼져 있거나, 코드 수정 뒤 재시작하지 않았다.

## 아키텍처

```
브라우저
  └─ Streamlit (app.py)
       ├─ 매매 복기·분석 (읽기 전용)
       └─ KIS 자동매매 (조작)
          화면에는 매매 로직이 없고 API만 호출한다.
            │ HTTP :8800
            ▼
FastAPI 서버 (api/main.py)
  ├─ TradingEngine: 시작 버튼을 누르면 백그라운드로 뜬다
  │    30분마다 종목별로
  │      1. 손절/트레일링 (exit_guard)
  │      2. 쿨다운·한도·VI 점검 (risk)
  │      3. 매매 판단 (signal_engine)
  │           일봉 지표 + 30분봉 + 뉴스 감성 + 밸류에이션
  │      4. 주문 의도 기록 → KIS 주문 → 체결통보 수신 → 체결 기록
  │
  ├─ PortfolioScheduler: 엔진과 별개로 돈다 (기본 꺼짐)
  │    트리거 → 종목 발굴 → LLM 제안 → 한도 검사 → PROPOSED 저장
  │    사람이 승인하면 active_target_weights에 반영
  │

            │

   ▼        ▼                  ▼
 SQLite    KIS OpenAPI       외부 데이터
 (모든      REST + 체결통보    네이버 금융, Gemini,
  기록)     웹소켓             CNN Fear & Greed
```

몇 가지 설계 선택이 있다.

- 엔진은 API 서버 프로세스 안에서만 돈다. 브라우저를 닫아도 계속 돌고, Streamlit은 엔진을 직접 건드리지 않는다.
- 판단, 주문 의도, 체결, 포지션의 진입가와 고점을 모두 SQLite에 남긴다. 재시작하면 KIS 체결내역과 대조해서 상태를 복구한다. KIS는 주문 중복 방지 키를 지원하지 않기 때문에, 일치하는 주문이 둘 이상이면 추측하지 않고 `UNKNOWN`으로 멈춘다.
- 종목마다 처리를 분리해서 한 종목이 실패해도 나머지는 계속 돈다. 뉴스나 LLM 같은 보조 입력이 죽으면 그 시그널만 빠지고, 손절과 한도는 그대로 작동한다.
- AI는 제안까지만 한다. 제안을 만드는 일(스케줄러)과 반영하는 일(승인)을 나눠 놨다.
- LLM은 `core/llm/base.py` 인터페이스 뒤에 있어서 `LLM_PROVIDER`만 바꾸면 다른 제공자로 교체할 수 있게 해뒀다.
